Problem solved: In an order system, a crash between saving an order and publishing its event silently loses data, and two buyers competing for the last item can oversell stock. SmartOrder is designed so neither can happen.

What I built: A microservices platform of 4 services (auth, catalog, inventory, orders) behind Spring Cloud Gateway with Eureka service discovery. Services communicate through Kafka using the transactional outbox pattern and dead-letter topics, and a React frontend consumes the secured APIs.

Key outcomes

  • → Implemented the transactional outbox pattern so order and inventory events publish reliably and failed events land in dead-letter topics instead of disappearing.
  • → Designed inventory reserve/release workflows that stay consistent under competing stock updates, validated with 100+ concurrent order requests and zero oversell.
  • → Secured every API with JWT and RBAC across 3 roles.
  • → Containerized MySQL and Kafka with Docker for a repeatable local environment.
